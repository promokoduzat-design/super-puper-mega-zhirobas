## 1.3 Временно сохраняем работу

Репозиторий: `01-stash`. Текущая ветка: `feature-students`.

Создан `main.py` и первый коммит. Затем в новой ветке добавлена строка `print("Add student feature")` и создан неотслеживаемый файл `students.py` с содержимым `students = []`.

Выполнено:

```bash
git stash push -u -m "unfinished students feature"
git status --short
git stash list
git stash pop
git status --short
```

После сохранения рабочая директория была чистой, `main.py` вернулся к первой версии, а `students.py` временно исчез из рабочей директории. В списке stash появилась одна запись:

```text
stash@{0}: On feature-students: unfinished students feature
```

После `git stash pop` оба изменения восстановлены, запись stash удалена. Итоговый статус:

```text
 M main.py
?? students.py
```

**Ответ на вопрос:** опция `-u` нужна, потому что `students.py` был новым неотслеживаемым файлом. Обычный `git stash` сохраняет изменения отслеживаемых файлов, а `-u` дополнительно включает неотслеживаемые файлы.

## 2.6 Сравниваем Reset Soft и Reset Mixed

Для каждого режима создан отдельный репозиторий с двумя коммитами: `Add version 1` и `Add version 2`.

| Проверка | `02-reset-soft` | `02-reset-mixed` |
|---|---|---|
| Выполненная команда | `git reset --soft HEAD~1` | `git reset --mixed HEAD~1` |
| Коммит, на который указывает ветка | Первый | Первый |
| Содержимое app.py | Version 1 и Version 2 | Version 1 и Version 2 |
| Изменение второй версии в индексе | Да | Нет |
| Изменение второй версии в рабочем файле | Да | Да |
| `git status --short` | `M  app.py` | ` M app.py` |

В кратком статусе первая колонка показывает состояние индекса, вторая — состояние рабочего файла относительно индекса.

**Ответ для Soft:** `--soft` переместил указатель ветки на предыдущий коммит, сохранив индекс и рабочие файлы. Поэтому добавленная строка второй версии осталась подготовленной к коммиту. Её показывает `git diff --staged`, а обычный `git diff` пуст.

**Ответ для Mixed:** `--mixed` переместил указатель ветки и привёл индекс к первой версии. Рабочий файл сохранил обе строки, поэтому изменение второй версии осталось неподготовленным. Его показывает `git diff`, а `git diff --staged` пуст.

История после Soft:

```text
a0be253 Add version 1
```

История после Mixed:

```text
e358144 Add version 1
```

Вторые коммиты больше не входят в историю текущих веток. Они ещё доступны через reflog и ORIG_HEAD в сохранённых репозиториях.

## 2.7 Отменяем коммит через Revert

Репозиторий: `03-revert`.

Созданы три последовательных коммита: каждый добавил в `app.py` строку с очередной версией. Затем выполнена команда `git revert --no-edit HEAD`. Опция `--no-edit` использует стандартное сообщение нового коммита без открытия редактора.

История после отмены:

```text
78fc10c Revert "Add version 3"
1ffd382 Add version 3
2edad7b Add version 2
b8efe1e Add version 1
```

Итоговое содержимое `app.py`:

```python
print("Version 1")
print("Version 2")
```

**Ответ на вопрос:** `git revert` создал новый коммит, который отменил изменения третьего коммита. Исходный третий коммит остался в истории, поэтому теперь в ней четыре коммита. Удалена строка `Version 3`, рабочая директория чистая.
